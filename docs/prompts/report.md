# 报告提示词 · 终版

- **当前版本**：v1.1（2026-11-03）
- **维护**：队员 E（泳道3 AI 工程）
- **调用位置**：`scripts/gen_reports.py`（离线批量预生成）、`app/api/report/[model]` 的 POST（按需生成）
- **落盘位置**：`data/reports/<model_id>.json`
- **模型**：`qwen-plus`（主）；长报告可切 `glm-5.3-flash`（deep，注意它是推理模型，`max_tokens` ≥ 3000）

> v1.1 的核心变化：**结论先由脚本按四条规则算死，模型只负责把结论写成人话**。
> 原因：v1.0 让模型自己套规则，实测出现过「95新折价 79% 却判 buy」「把 79% 的
> 二手/新机价比说成 79% 折价」两类错误。报告要拿去答辩，结论必须可复现。

---

## 一、输入怎么拼（脚本负责，模型只负责写）

`gen_reports.py` 按下面顺序拼成一条 user 消息，**没有的部分写"暂无数据"，绝不省略不写**（省略会让模型自己编）：

```text
【机型】{brand} {name} {variant}，首发价 {launch_price} 元
【新机现价】{jd 现价} 元（{captured_at} 采集，来源 {source}）
【商品页】{jd_url}
【历史价摘要】共 {n} 个采样点：最低 {min}、最高 {max}、中位 {median}；当前价处于第 {p} 百分位；近 7 天变化 {±x}%
【二手样本摘要】共 {n} 条：99新 中位价 …；95新 中位价 …；9成新 …；8成新 …；大修 …
【样本摘录】{前 6 条：标题（价格/成色；卖家描述）}
【避坑知识】{命中的 knowledge 条目，每条：标题 + 正文 + 来源}
【评测摘要】{corpus_<model_id>.json 有就列，没有就写暂无数据}
【规则预判】buy|wait|avoid（规则N：一句话规则命中说明）
【价格位置提示】{近30天第p百分位，中位价…，当前价…；没有历史价就写“新机现价…暂无30天历史价可对比”}
【结论提示】{脚本按规则写好的结论句，含关键数字}
```

> 评测摘要必须是**真实抓取或人工整理**的内容，脚本不生成。没有就留空，模型在
> `sources` 里只填商品页——这是预期行为，不是 bug。

## 二、提示词正文

**system**：

```text
你是一个冷静、克制的数码产品买手。你的读者是想买二手或降价新机、但不懂行的普通人。
价格、成色、风险必须依据用户给出的数据，不编造数据、不编造来源；
产品定位和通用使用体验可以用公开常识，但不要编造型号、参数或价格。
只输出一个 JSON 对象，不要 markdown 代码块，不要解释文字。
```

**user**（模板，`{...}` 由脚本替换）：

```text
{上面拼好的输入}

请据此生成一份购买决策报告，输出这个 JSON：

{
  "verdict": "buy|wait|avoid",
  "verdict_reason": "一句话结论，40 字内，要具体到价格或风险，不要复述规则编号",
  "price_position": "一句话说明当前价在历史里的位置，必须带百分位或差价，40 字内",
  "pros": ["优点，每条 20 字内，3 条，必须基于输入数据"],
  "cons": ["缺点，每条 20 字内，3 条，必须基于输入数据"],
  "pitfalls": ["这台机器最容易踩的坑，每条 25 字内，3 条，要能直接照着做"],
  "sources": [{"title": "来源标题", "url": "来源链接"}]
}

硬性约束：
- verdict 必须等于上面【规则预判】给出的结论，一个字都不能改。
- pros / cons / pitfalls 三个数组各写 3 条，都不能为空；不要用“数据不足”“暂无可确认”这类占位句凑数。
- sources 只能填写输入里出现过的链接，一条都不许自己造；输入里没有链接就输出空数组 []。
- 不要写“根据某某评测”这种没有具体来源的话。
- 所有价格单位是人民币元，不要换算。
```

## 三、四条判定规则（脚本执行，v1.1 校准）

按顺序执行，先命中先定：

| # | 条件 | 结论 |
|---|---|---|
| 1 | 二手样本的**卖家描述**出现 进水/大修/扩容/翻新/监管/有锁/主板维修，且避坑知识命中同类风险 | `avoid` |
| 2 | 当前价处于近 30 天**第 30 百分位以下**，且二手 95新中位价 ≤ 新机现价的 **80%** | `buy` |
| 3 | 当前价处于第 70 百分位以上，或近 7 天涨幅 > 5% | `wait` |
| 4 | 其余情况 | `wait`（等更好的价格点） |

**为什么 v1.1 把买入线从 65% 调到 80%**：

- 任务书 v1.0 写的是 65%。用种子数据实测：6 款 T1 的 95新中位价 / 新机现价 =
  77.5%～80.0%，65% 这条线**永远不触发**，20 份报告会全部是 `wait`。
- 65% 的含义是「二手要比新机便宜 35%」。iPhone 这类保值机型，95新通常只比新机
  便宜 20%～25%，65% 不是真实市场的买入线，是一条永远不会亮的灯。
- v1.1 把演示线校准到 80%（二手比新机低 20%），仍保留「近 30 天第 30 百分位以下」
  的前置条件。65% 不再作为判据，但在答辩时可以说明：这是按种子数据校准的演示线，
  接真实闲鱼数据后应回归到按品类分档的阈值。
- 规则 1 只看 `condition_text`（卖家描述），不看标题里的成色档位。否则标题里的
  「大修或功能缺陷」五个字会把所有机型都误判成 `avoid`。

## 四、输出契约（前端按这个渲染）

```json
{
  "model_id": "iphone-13-128g",
  "verdict": "buy",
  "verdict_reason": "当前价近30天第13百分位，二手95新为新机价79.1%，低于80%买入线",
  "price_position": "近30天第13百分位，中位价3797元，当前价3779元",
  "pros": ["现价3779元，比首发价低2220元", "近7天价格稳定，波动仅-0.1%", "128G容量满足日常使用"],
  "cons": ["二手95新中位价2989元，仅比新机低790元", "评测语料未接入，性能结论缺实测", "需核对电池健康与维修史"],
  "pitfalls": ["只给IMEI不给序列号，无法查扩容与保修", "N/F开头型号冒充零售新机", "电池健康低于80%却标95新"],
  "sources": [
    { "title": "京东商品页", "url": "https://search.jd.com/Search?keyword=iPhone%2013%20128G&enc=utf-8" }
  ],
  "generated_at": "2026-11-03T18:50:00+08:00",
  "generator": "qwen-plus",
  "rule": 2,
  "rule_text": "当前价处于近30天第13百分位，且二手95新中位价为新机价79.1%（≤80%，v1.1 校准）",
  "metrics": {
    "current_price": 3779,
    "percentile_30d": 13,
    "used_95_median": 2989,
    "used_95_ratio_pct": 79.1,
    "week_change_pct": -0.1,
    "used_sample_count": 12
  }
}
```

**三色徽章对应**：`buy` = 绿（值得买）、`wait` = 黄（等降价）、`avoid` = 红（别买）。

> ⚠️ 给 B（验机/报告页）的约定：`sources` 是**对象数组**（`title` + `url`），不是字符串数组。
> 前端 `components/report/types.ts` 已做兼容：字符串会转成无链接的来源，不会崩。

## 五、脚本侧后置校验（对应 `gen_reports.py` 的 `validate`）

| 检查 | 不通过怎么办 |
|---|---|
| `verdict` 必须等于规则预判 | 直接改回预判值；重试时在提示词里点名 |
| `pros/cons/pitfalls` 各 ≥2 条、无“数据不足”占位 | 先重试 1 次；仍缺就补价格/风险类兜底句 |
| `verdict_reason` 含具体数字且逻辑不打架 | 规则 4 的 wait 直接用脚本结论句，避免“折价/价比”歧义 |
| `price_position` 有数字；无历史价时不许写“第N百分位” | 用 `make_price_position` 的确定句替换 |
| `sources[].url` 必须出现在输入文本里 | 删掉伪造条目；全删光就保留商品页那一条 |

## 六、人工审清单（E 的活，每份报告 30 秒）

- [ ] `verdict` 和你的常识一致吗？（一台 95新 iPhone 13 卖 4500 却判 buy，就是错的）
- [ ] `sources` 里的链接点开是真实存在的页面吗？
- [ ] `pitfalls` 是这台机器**特有**的坑，还是所有手机都适用的套话？
- [ ] `price_position` 的数字和 `prices_history.json` 对得上吗？
- [ ] `verdict_reason` 里的“折价/价比”有没有说反？（79.1% 是“二手价是新机价的 79.1%”，不是“折价 79.1%”）

## 七、版本记录

### v1.1（当前）— 相对 v1.0

| # | 改动 | 原因 |
|---|---|---|
| 1 | 四条规则改由脚本先算，模型只写理由 | 模型自己套规则会判错，且同一机型两次结论可能不同 |
| 2 | 买入线 65% → 80%（演示校准） | 种子数据 95新/新机价 77.5%～80%，65% 永远不触发，20 份全 wait |
| 3 | 输入增加【商品页】【样本摘录】【价格位置提示】【结论提示】 | 模型缺链接可引用、缺样本描述会编坑；没有历史价时会编百分位 |
| 4 | `sources` 从字符串数组改成对象数组 | 前端要渲染可点链接；字符串来源会丢链接 |
| 5 | `verdict_reason` 增加“折价/价比”校验 | 实测出现过“折价 79%”把比率当折扣的错话 |

### v1.0
首版。三条硬规则的目的：**让 verdict 可复现**。不写规则的话，同一个机型今天问是 buy、明天是 wait，答辩现场被追问就解释不清。
